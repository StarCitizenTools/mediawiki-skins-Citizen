# Upgrading across versions

Citizen serves CSS and JS fresh on every page view, but wikis cache HTML —
in the parser cache, CDN or Varnish layers, and `$wgUseFileCache`. After an
upgrade, cached pages generated by the old version meet the new styles, which
can break their appearance until every cache has expired or been purged.

Citizen ships a compatibility layer for exactly this window.

## The compat flag

Set `$wgCitizenCompat = true;` **before** upgrading. While enabled, Citizen
serves compatibility styles so HTML generated by versions up to **6 minor
releases** back keeps rendering acceptably — readable and usable, though not
always pixel-perfect. The styles ride the normal render-blocking stylesheet,
so cached pages are corrected at first paint, including for no-JS visitors.

The lifecycle:

1. Enable the flag.
2. Upgrade Citizen.
3. Wait out your longest cache lifetime (parser cache expiry, CDN TTL, or
   file cache age — whichever is longest), purging gradually if you prefer.
4. Disable the flag.

Leaving it enabled costs only a few KB of extra CSS per page view — wikis
that deploy continuously can simply leave it on.

## Release cache statuses

Each release's notes state its cache status:

* **clean** — no cached-HTML impact; upgrade freely.
* **covered by compat** — enable the flag across the upgrade.
* **purge required** — some pages cannot be bridged by styles alone; plan a
  cache purge (see below). The flag still covers everything else.

## Wiki farms

Enable the flag farm-wide (it is inert for wikis that have no stale pages),
upgrade, then purge caches wiki-by-wiki at whatever pace your infrastructure
tolerates, and disable the flag when done. If you jumped more than 6 minor
releases, expect pages older than the window to need a purge.

## Purging gradually

To spread the re-parse load instead of purging everything at once:

* Step `maintenance/purgeParserCache.php --age <seconds>` down over several
  days (start with the oldest entries).
* Or stage `$wgCacheEpoch` forward per wiki, a group of wikis at a time.
* Before a *planned* upgrade, temporarily lower `$wgParserCacheExpireTime`
  a week in advance so no cache entry is older than that when you deploy.
